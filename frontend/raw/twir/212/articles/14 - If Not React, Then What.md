# Item 14: If Not React, Then What?

Source: [https://infrequently.org/2024/11/if-not-react-then-what/](https://infrequently.org/2024/11/if-not-react-then-what/)

Summary:
This essay critiques React’s continued dominance in new projects, arguing that it is now legacy technology unsuited for modern performance and accessibility needs. The author advocates for minimizing client-side complexity, favoring HTML/CSS over JavaScript, and re-examining tech stack choices based on user needs rather than framework popularity. The piece encourages teams to run bake-offs and focus on engineering constraints, not trends or orthodoxy.

Key takeaways:
- React is described as legacy and ill-suited for new projects; teams should consider alternatives.
- Minimize client-side code for better performance, resilience, and accessibility.
- Tech choices should be driven by user needs and objective constraints, not framework trends.
- Encourages experimentation and critical evaluation of stack decisions.
