# Item 4: Avoiding premature abstraction with Unstyled React Components

Source: [https://buildui.com/posts/avoiding-premature-abstraction-with-unstyled-react-components](https://buildui.com/posts/avoiding-premature-abstraction-with-unstyled-react-components)

Summary:
The article advocates extracting unstyled components to share behavior (like loading spinners) without coupling to specific styles, avoiding premature or rigid abstractions. It demonstrates how to refactor a loading button into a reusable, unstyled component, allowing consumers to provide their own styling. This approach enhances flexibility and maintainability, especially as design requirements evolve.

Key takeaways:
- Prematurely abstracting both behavior and styles leads to rigid, hard-to-maintain components.
- Unstyled components let you share logic/UI patterns while keeping styling flexible.
- Adding a className prop allows consumers to style components as needed.
- Encourages separating concerns: behavior vs. presentation.
