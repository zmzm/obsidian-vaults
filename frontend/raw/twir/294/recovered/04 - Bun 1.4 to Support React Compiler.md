# Support React Compiler w/ Bun's built-in bundler · Issue #24356 · oven-sh/bun · GitHub

### What is the problem this feature would solve?

React Compiler recently reached v1.0 (<https://react.dev/blog/2025/10/07/react-compiler-1>). If Bun aims to replace Vite and other bundlers, it would be nice if it supported most of the same plugins, especially React Compiler.

Thus I am requesting support for React Compiler both with `bun build` CLI and `Bun.build` JS API (<https://bun.com/docs/bundler>).

Please note that this has *nothing to do* with Next.JS nor Turbopack. If that's your issue, please see the now overrun issue [#23554](https://github.com/oven-sh/bun/issues/23554)

### What is the feature you are proposing to solve the problem?

React Compiler not only provides significant speed improvements, it also changes how we write React code. A lot of stuff doesn't need to be memoized any more, so the way I write components is different depending on if React Compiler is enabled. Thus switching build tools isn't merely reconfiguring the build process, it also trickles down into all the React Components.

### What alternatives have you considered?

Use Vite, Webpack, Rollup, or a different bundler.

For googlers coming here, I adapted this from mnpenner's package above:

1. **install deps: `bun i -d @babel/core babel-plugin-react-compiler`**
2. **create `bun-plugin-react-compiler.ts`**

```
import babel from "@babel/core";
import BabelPluginReactCompiler from "babel-plugin-react-compiler";

const options = {}; // options passed to react-compiler

const reactCompiler: Bun.BunPlugin = {
	name: "react-compiler",
	setup({ onLoad }) {
		onLoad({ filter: /\.[jt]sx$/ }, async args => {
			const input = await Bun.file(args.path).text();
			const result = await babel.transformAsync(input, {
				filename: args.path,
				plugins: [[BabelPluginReactCompiler, options]],
				parserOpts: { plugins: ["jsx", "typescript"] },
				ast: false,
				sourceMaps: false, // could use Bun.env.NODE_ENV == "dev"
				configFile: false,
				babelrc: false,
			});

			if (result?.code == null) throw new Error(`Failed to compile ${args.path}`);

			return { contents: result.code, loader: "tsx" };
		});
	},
};

export default reactCompiler;
```

3. **use it**

either in Bun.build:

```
import reactCompiler from "./bun-plugin-react-compiler";

Bun.build({
  plugins: [reactCompiler],
  // ...
});
```

or in bunfig.toml (e.g. for HTML imports):

```
[serve.static]
plugins = ["./bun-plugin-react-compiler.ts"]
```

This issue should be closed as resolved: [#32504](https://github.com/oven-sh/bun/pull/32504)

Thanks for opening this, and for publishing the plugin that tided people over in the meantime. React Compiler is now built into Bun's bundler as `bun build --react-compiler` and `Bun.build({ reactCompiler: true })` ([#32504](https://github.com/oven-sh/bun/pull/32504)) -- the upstream compiler passes run natively inside the bundler, no Babel plugin needed -- and it is in the current canary ahead of the next release.

**What I ran** (in Docker, `oven/bun:1.3.14` vs canary `1.4.0-canary.1`):

```
// App.tsx
import { useState } from "react";
export function Counter({ label }: { label: string }) {
  const [n, setN] = useState(0);
  const onClick = () => setN(n + 1);
  return <button onClick={onClick}>{label}: {n}</button>;
}
// shell
bun build ./App.tsx --external react --external 'react/*' --react-compiler | grep compiler-runtime
// or JS API
const r = await Bun.build({ entrypoints: ["./App.tsx"], external: ["react", "react/*"], reactCompiler: true });
console.log((await r.outputs[0].text()).includes("react/compiler-runtime") ? "OK" : "BUG");
```

**Results**

- **Bun 1.3.14:** `bun build --react-compiler` and `Bun.build({ reactCompiler: true })` both produce the untransformed component (no react/compiler-runtime import, no \_c() memo cache); repro printed BUG for both the CLI and JS API paths.
- **Canary:** both `bun build --react-compiler` and `Bun.build({ reactCompiler: true })` emit `import { c as _c } from "react/compiler-runtime"` and a `_c(6)` memo-cache-rewritten Counter; repro printed OK for both paths, exit 0.

This is in the current canary now (`bun upgrade --canary`) and will be in Bun v1.4.0. If it still reproduces for you there, comment here and we'll reopen.
