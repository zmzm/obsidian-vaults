# Item 6: Dissecting Partial Pre Rendering

Source: [https://www.nikhilsnayak.dev/blogs/dissecting-partial-pre-rendering](https://www.nikhilsnayak.dev/blogs/dissecting-partial-pre-rendering)

Summary:
This deep dive explains partial pre-rendering (PPR) in Next.js, situating it among other rendering strategies like SSR, CSR, and SSG. It discusses the motivation for PPR, its benefits in combining static and dynamic rendering, and addresses common pitfalls in client-side rendering such as poor SEO and "loading spinner hell."

Key takeaways:
- PPR allows static portions of a route to be pre-rendered and cached, with dynamic content streamed in.
- Combines the best aspects of SSR, CSR, and SSG for performance and SEO.
- Addresses common CSR issues like poor SEO and excessive loading states.
- PPR is experimental in Next.js 14 and aims to optimize both developer and user experience.
